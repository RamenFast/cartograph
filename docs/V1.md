# Cartograph — V1 (the shippable core)

> Written 2026-07-03 after a full code-vs-docs audit (the running binary, not the prose).
> ⚠ **Historical build plan — the build drifted from it in known places** (audit F27):
> the GTK list shipped as `GtkListBox`, not the `GtkColumnView` planned below; **TLS SNI
> was deliberately dropped** (ECH is eroding it — passive DNS took its slot); the shared
> daemon/ctl surface (2026-07-11) postdates this plan entirely. Trust `NEXT-SESSION.md`
> and `--schema` for current state; read this for why V1 was scoped the way it was.
> This is a **scope decision plus a sequenced build plan.** It does not replace VISION.md —
> it picks the *first slice of it that is worth shipping on its own* and orders the work so
> every step ends with something you can open and use. The maximal vision (the constellation
> map, DVR, the visible-OS arc) is still north; this is the road that actually reaches it.

## The call

The foundation is real and good: `surveyor snapshot` already names the processes on this box
talking to the internet, with per-flow bytes, RTT, v6, service, and exposure — in ~30 ms,
5.5 MB RSS, 50/54 tests green, one clean view-model behind three renderers. What is **missing
is the entire thing that makes it special:** real identity (you see IPs, not `github.com`) and
a real UI (the GTK "window" is a monospace `GtkLabel`). V1 closes exactly that gap and nothing
else.

**V1 is one loop, done beautifully:**

> *See, in real time and with real names, every process on this machine and who it is talking
> to — and click any flow to know **why**.*

That is Little-Snitch-meets-an-explorable-map, and no single Linux tool owns it (OpenSnitch is
blocking-first and plain; `sniffnet` is pretty but weak on process attribution; Wireshark is
packets, not places). Our attribution core is already ahead on the hard part.

### In scope for V1 · out of scope for V1

| In V1 | Deferred (post-V1) |
|---|---|
| Real identity: rDNS + offline GeoIP/ASN → names, owners, countries | The constellation / orbit force-directed **map** (the hardest 20%) |
| A real GTK app: `ColumnView` + selection + a docked **"Why" panel** | `atlas` / BEAM multi-observer fabric (see "The atlas call") |
| eBPF hybrid fusion: realtime, short-lived flows, UDP/QUIC bytes | DVR / time-travel, persistence/sqlite history |
| Passive DNS + TLS SNI → *true* hostnames | LLM "explain / postcard", cross-resource GPU fusion |
| Local app icons + category/risk badges | XDP allow/block/throttle enforcement |
| The existing agent-native NDJSON surface, extended with the new fields | Deep T2 payload capture / packet dissection |

Nothing in the right column is cancelled — it is *sequenced after* a lovable V1 exists, and V1
is deliberately built so each lands as an addition, not a rewrite (the `Source` seam, the
frame codec's trailing-field additivity, the `Focus` seam all already support this).

## The sequence

Four steps. Each ends shippable and demoable. Each ships its GTK surface in the same step (D21).

### S1 — Real identity, unprivileged (the "IPs → github.com" win) · *start here*

The single biggest perceived-value jump, and it needs **no new privilege** — pure enrichment
over data we already have. Turns `2607:6bc0::10` into `anthropic.com · AS13335 Cloudflare · US`.

**Data model** (`src/lib/flow.zig`, on `Flow`):
- `remote_name: Str(128)` — hostname (rDNS now; upgraded to SNI/passive-DNS in S3).
- `asn: u32`, `as_org: Str(64)`, `country: [2]u8` — from the offline MMDBs.

**New code:**
- `src/lib/mmdb.zig` — a small **pure-Zig MaxMind DB reader** (the format is simple; keeps the
  base build dependency-free per the ethos). Pure, offline, synchronous → looked up inline each
  tick. Unit-tested against a tiny embedded fixture. *(Lib, not capture: it's a reusable pure
  decoder, and parity wants it below the renderers.)*
- `src/capture/enrich.zig` (surveyor-side) — owns:
  - a **`Resolver`**: 2–4 worker threads draining a queue of unresolved `Addr`, calling
    `getnameinfo` (PTR), writing into a mutex-guarded cache with a negative-cache + TTL. The
    1 Hz tick only ever *reads* the cache — never blocks on DNS.
  - a **`GeoDb`**: two loaded MMDBs (ASN + Country), path from `--geoip <dir>`.
  - `decorate(flows: []*Flow)`: fills the identity fields on the live table's `Flow`s (writes
    *through* the `[]*Flow` pointers `table.snapshot` already returns) and queues cache misses.
- Call `enrich.decorate` in surveyor's `snapshot` and `streamLoop` right after `table.snapshot`.
  Capture (`capture.zig`) stays pure — enrichment is a clean post-pass.

**Wire + projections** (coordinated, single-repo, all consumers rebuild together):
- Extend the `flow_upsert` frame in `src/lib/ipc.zig`: append `remote_name` (u8-len+bytes, like
  `comm`), `asn` (u32), `as_org` (u8-len+bytes), `country` (2 bytes). Bump `protocol_version`
  → 3. Extend the parity test corpus.
- Add the same fields to `writeFlowFields` + the `writeSchema` field list in `src/lib/json.zig`
  (keep the emit-order contract the schema documents).

**Renderer surface (same step):** TUI + GTK show `name (org · CC)` where known, falling back to
the IP. This is the visible headline of V1.

**Data files:** GeoLite2 needs a MaxMind account; **DB-IP Lite** (CC-BY, no account) is the
zero-friction default — ship `scripts/fetch-geoip.sh` writing to
`~/.local/share/cartograph/geoip/` (data, **never** committed — licensing + size + privacy).
`--geoip` overrides. Missing DB = graceful degrade to rDNS-only, loudly noted (never silent).

**Tests:** mmdb decode (fixture), resolver cache hit/negative/TTL, extended IPC parity, JSON
field-order. **Effort: medium-high** (the async resolver is the only fiddly part).

### S2 — The GTK frontend becomes an application (`ColumnView` + "Why" panel)

Today's GTK is a non-interactive label that rebuilds the whole table as one markup string every
tick (the efficiency hotspot *and* the reason it can't animate). Replace it with a real widget
tree.

- Swap the `GtkLabel` for a **`GtkColumnView`** backed by a `GListStore` of row objects, updated
  **per-row** (kills the full-rebuild cost, enables smooth "motion = truth").
- `GtkPaned`: table left, a docked **"Why" panel** right. Row selection narrates the selected
  flow: process · exe · pid · **parent** (small `/proc` ppid add) · service/category/exposure ·
  `name (org · country)` · up/down bytes · RTT · first/last seen · fresh. **Every field already
  exists after S1** — this is assembly, not new capture.
- The narration generator goes in `src/lib/why.zig` (`describe(w, *Flow)`), a pure function over
  `Flow`, so the TUI can show the same "why" on select (parity).
- Wire row-select → `SessionState.setFocus` → `user_state{focus}` upstream: the `Focus`/R1
  **shared cursor finally gets its real UI** (NEXT-SESSION's standing next task), and the "Why"
  panel is its first consumer.

**Effort: high** (real GTK4 `ColumnView` via C FFI is the biggest UI lift) — but it is the step
that turns "a flow table in a window" into "an app," so it's the one that earns the vision.

### S3 — Realtime for real (eBPF hybrid fusion + UDP bytes + true hostnames)

The seam (`Source` union) exists and eBPF attach is already verified; this makes it *useful*.

- **Fuse** `.bpf` = inet_diag baseline (table + TCP bytes) **+** eBPF events (births/deaths/
  short-lived/attribution). eBPF *adds to* the live table instead of replacing it (fixes the
  `snapshot --bpf` = 0-rows-at-idle problem, ROADMAP M3).
- eBPF **socket-create → PID map** → catches short-lived connections (the security-relevant
  ones the 1 Hz poller misses) and retires the O(procs×fds) `/proc` walk.
- eBPF `tcp_sendmsg`/`udp_sendmsg` counters → **UDP/QUIC throughput** (today's blind spot; HTTP/3
  is a large, growing share of real traffic).
- **Passive DNS** (the box's own :53 answers) + **TLS SNI** (first bytes of :443) → upgrade S1's
  rDNS `remote_name` to the *true* hostname.
- Needs caps: `setcap cap_bpf,cap_perfmon,cap_net_raw,cap_net_admin+ep surveyor` (Ben runs it;
  the frontend is never privileged — the boundary finally becomes load-bearing).

**Effort: high** (largest engineering), but structurally de-risked by the existing seam.

### S4 — The visual identity layer (logos + risk rings)

Where it starts to *look* like the vision (still short of the map).

- **Local app icons**: exe → `.desktop` → XDG icon theme (offline, unprivileged), resolved in
  `src/lib`, drawn by GTK.
- **Remote logos**: favicon / brand-pack, cached + rate-limited + **opt-in** (the privacy posture
  — the tool watching your traffic never leaks it, and shows its *own* fetches on the map).
- **Risk/impact rings**: the decomposable score (DESIGN-LANGUAGE §2/§4) → confidence/impact rings
  drawn in GTK, scoring emitting `Reading`s.

**Effort: medium-high.**

## The atlas call (a scope decision to ratify)

**V1 defers `atlas` / BEAM.** It serves the maximal "human + their AIs watching one screen"
vision, but it adds an entire second runtime and a distribution/presence concern to a solo
project — and **V1's whole value is fully deliverable single-observer.** Critically, the
**agent-native NDJSON surface already exists** (`serve --json`, `--schema`): an AI can already
watch the exact live truth the GUI renders. That covers most of "AI co-observation" *without*
BEAM. surveyor's one-client-at-a-time limit is a real V1 gap only for *multiple* observers;
a small Zig multi-client accept+broadcast loop covers "me + my agent" if/when needed, and
`atlas` remains the right home for many-observer presence **when the maximal vision is funded
in time.**

This scopes — does **not** cancel — the "atlas is essential" stance: essential to the *maximal*
vision, out of *V1*. Proposed as **D26** for Ben to ratify.

## What "V1 done" looks like

Open the GTK app. It shows, live and moving, every process on your machine and — by name, owner,
and country — who each is talking to. Click any flow and a panel tells you, in plain terms, what
it is and why it exists. It catches the connection that lived for 40 ms. It runs cool enough to
leave open. An AI watching the same socket sees the same truth. *That* is worth shipping — and
it is the honest floor the constellation map, DVR, and the rest of VISION.md get built on next.
